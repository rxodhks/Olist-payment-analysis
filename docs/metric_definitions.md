# 분석 기준과 지표 정의서

분석 기준을 바꾸면 이 문서와 관련 쿼리를 함께 고친다.

## 분석 기준

| 항목 | 기준 | 근거 | 결정한 곳 |
| --- | --- | --- | --- |
| 분석 기간 | 2017-01 ~ 2018-08 | 2016-09 4건, 2016-11 0건, 2016-12 1건, 2018-09 16건, 2018-10 4건. 수요가 아니라 데이터 수집 시작·종료의 경계 효과이고, 2016-11이 비어 있어 2016-10도 연속성이 끊긴다 | `sql/02_scope.sql` |
| 분석 대상 주문 | `order_status = 'delivered'` | canceled, unavailable은 구매로 보지 않는다. delivered는 전체의 약 97%(96,478건) | `sql/02_scope.sql` |
| 고객 단위 | `customer_unique_id` | `customer_id`는 주문마다 새로 발급된다(ID당 최대 주문 1건). 사람 단위는 `customer_unique_id`(최대 17건) | `sql/01_customer_id.sql` |
| 매출 | 상품 금액 = `price + freight_value` | 결제액은 할부 이자 등 결제 조건의 영향을 받는다. 불일치 249건 중 결제액이 더 큰 232건의 대부분(229건)이 할부 | `sql/03_join_fanout.sql` |

## 집계 원칙

| 원칙 | 이유 |
| --- | --- |
| 1:N 테이블은 JOIN 전에 주문 단위로 먼저 집계한다 | 그냥 JOIN하면 상품 N개 × 결제 M건 = N×M행이 되어 합계가 부푼다(결제 합계 +26.9%) |
| 합계는 다 더한 뒤 한 번만 반올림한다: `ROUND(SUM(x))` | `SUM(ROUND(x))`는 건별 반올림 오차가 누적된다 |
| 원천 문자열은 `TO_NUMBER`로 명시적으로 변환한다 | 암묵적 변환은 형식이 다른 값이 섞이면 오류가 난다 |

## 아직 검증하지 못한 가설

- 결제액이 상품 금액보다 작은 17건: 할인 수단 사용으로 추정. 바우처 결제는 이 17건에 없었다.
